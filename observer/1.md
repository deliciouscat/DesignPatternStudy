# 문제

**시나리오:**
주식 시세 앱을 만들고 있습니다. 주식 가격이 변동하면 이를 여러 컴포넌트(차트, 알림 매니저, 포트폴리오, 통계)에 즉시 알려야 합니다. 새로운 옵저버가 동적으로 추가되거나 제거될 수 있으며, 각 옵저버는 독립적으로 동작합니다.

**요구사항:**
1. Subject(주체): `Stock` - 주식 정보 관리
2. Observers(옵저버): `PriceChart`, `NotificationManager`, `Portfolio`, `StatisticsCollector`
3. Stock 클래스:
   - `symbol`: 주식 심볼 (예: "AAPL")
   - `price`: 현재 가격
   - `setPrice(newPrice)`: 가격 업데이트 → 모든 옵저버에 알림
   - `attach(observer)`: 옵저버 등록
   - `detach(observer)`: 옵저버 제거
   - `getObservers()`: 등록된 옵저버 목록 반환
4. 각 옵저버는 `update(stock)` 메서드 구현
   - `PriceChart`: 새로운 가격을 차트에 추가
   - `NotificationManager`: 가격 변동률이 5% 이상이면 알림 발송
   - `Portfolio`: 자신의 포트폴리오에 이 주식이 있다면 현재 자산 재계산
   - `StatisticsCollector`: 가격 통계(최고가, 최저가, 평균) 업데이트

**예시 사용 시나리오:**
```py
// 주식 생성
apple = Stock("AAPL", 150.0)

// 옵저버 생성
chart = PriceChart()
notification = NotificationManager()
portfolio = Portfolio("내 포트폴리오")
stats = StatisticsCollector()

// 옵저버 등록
apple.attach(chart)
apple.attach(notification)
apple.attach(portfolio)
apple.attach(stats)

// 가격 업데이트 → 모든 옵저버에 자동 알림
apple.setPrice(155.0)  // 가격이 5% 상승
// → chart가 새 가격 기록
// → notification이 "AAPL 가격이 5.0% 상승했습니다!" 메시지 전송
// → portfolio가 자산 재계산
// → stats가 통계 업데이트

// 특정 옵저버 제거
apple.detach(notification)

// 이제 notification은 알림을 받지 않음
apple.setPrice(160.0)
```

**추가 요구사항:**
- 같은 옵저버를 중복으로 등록할 수 없음
- 옵저버 제거 시 존재하지 않으면 무시
- 옵저버는 업데이트 중에 자신을 제거할 수 없음 (반복 중 컬렉션 수정 방지)
- 옵저버들의 업데이트 순서는 등록 순서대로

# 평가

## 평가

### 잘 이해한 부분

- Subject(`Stock`)가 observers 리스트를 보유하고, `attach`/`detach`/`getObservers`로 관리한다는 구조적 뼈대는 정확히 파악했습니다.
- 가격이 변경되면 등록된 observer들을 순회하며 알림을 보내는 흐름 자체는 맞습니다.

---

### 패턴 관점에서의 문제점

**1. Observer의 `update(stock)` 메서드 누락 — 가장 핵심적인 문제**

Observer Pattern의 핵심은 Subject가 자신의 상태를 Observer에게 전달하는 것입니다. 표준 구조는 Subject가 `observer.update(self)` 를 호출하고, Observer는 전달받은 Subject에서 필요한 데이터를 꺼내 씁니다. 답안에서는 `o.notify()`로 호출하면서 **아무 정보도 전달하지 않습니다.** Observer가 어떤 주식이, 얼마로 변동됐는지 알 방법이 없습니다.

**2. Observer 인터페이스(추상 클래스) 미정의**

Observer Pattern은 모든 Observer가 공통 인터페이스(예: `update(stock)`)를 구현한다는 계약에 기반합니다. 이 인터페이스가 없으면 Subject는 Observer의 구체적인 타입을 알아야 하고, 패턴의 의미가 사라집니다.

**3. 요구된 Observer 타입들을 다른 개념으로 대체**

문제는 `PriceChart`, `NotificationManager`, `Portfolio`, `StatisticsCollector`라는 각기 다른 역할의 Observer를 정의하고, 각각이 `update(stock)`에서 독립적으로 다르게 반응하는 구조를 요구했습니다. 답안은 이것을 `User` 단일 클래스로 대체하고 `wantNotify`라는 함수 목록으로 처리했는데, 이는 Observer Pattern보다는 이벤트 핸들러 구독 시스템에 가깝습니다.

**4. `buyStock`이 `attach`와 연결되는 흐름 불명확**

`john.buyStock(apple)` 이후 어떻게 john이 apple의 observer로 등록되는지 코드에 나타나 있지 않습니다. Observer Pattern에서 등록(`attach`)은 명시적으로 이루어져야 합니다.

**5. 추가 요구사항 전혀 미반영**

- 중복 등록 방지 없음
- `detach` 시 존재하지 않으면 무시하는 처리 없음
- 순회 중 컬렉션 수정 방지 없음

**6. `publishNews`의 로직 오류**

```python
for o in observers:
    self.news.append(~)  # 순회할 때마다 news가 중복 추가됨
    o.notify()
```

`self.news.append(~)`는 루프 밖에서 한 번만 해야 합니다.

### 총평

Observer Pattern의 **"Subject가 변경되면 등록된 Observer들에게 자동으로 알린다"**는 대전제는 이해하고 있습니다. 그러나 패턴의 핵심 구조인 **공통 Observer 인터페이스** + **`update(subject)` 호출로 상태 전달** + **각 Observer의 독립적인 반응 로직** 이 세 가지가 빠져 있어서, 패턴을 구현했다기보다는 자체적인 알림 시스템에 가까운 설계가 되었습니다.
