# 문제

**시나리오:**
당신은 도서관의 **대출 및 반납 시스템**을 개발하고 있습니다. 사용자가 책을 빌리면 자동으로 **반납 기한**이 정해지고, 기한이 가까워지면 **알림**을 보냅니다. 반납하지 않으면 **벌금**이 누적되고, 모든 거래는 **감사 로그**에 기록됩니다.

**기본 시나리오:**
```
사용자 Alice가 "Python 완벽 가이드" 책을 빌린다
  ↓
📋 시스템이 알아야 할 것:
   - 이 책의 정보(제목, ISBN, 정가)
   - Alice의 회원 정보
   - 현재 날짜/시간
   - 대출 기한 계산 규칙 (일반 책: 14일? 참고도서: 7일? 시즌별로 다를 수 있음)
   - 어디에 기록할 것인가 (DB? 파일?)
   - 누구에게 알릴 것인가 (카톡? 이메일? SMS?)
   - 벌금을 어떻게 계산할 것인가 (일일 500원? 주말 제외?)
  ↓
이 모든 것을 한 `LoanService` 클래스에 우겨넣으면 → 💥 강한 결합, 테스트 불가능, 정책 변경 시 코드 수정 폭탄
```

**요구사항:**

1. **핵심 동작:**
   - `borrowBook(member_id, book_id)`: 책 대출 → 기한 계산 → 기록 → 알림
   - `returnBook(member_id, book_id)`: 책 반납 → 벌금 계산(있으면) → 기록
   - `sendReminderNotification(member_id)`: 반납 기한 3일 전 알림 전송
   - `calculateOverdueFine(days_overdue)`: 연체 벌금 계산

2. **정책은 외부에서 주입 가능:**
   - 대출 기한 정책 (일반/참고도서/시즌별로 다를 수 있음)
   - 알림 채널 (카톡/이메일/SMS/앱 푸시 — 우선순위나 조합이 바뀔 수 있음)
   - 벌금 계산 방식 (일일 500원? 주말 제외? 최대 금액 제한?)
   - 저장소 (실제 DB? 테스트용 메모리?)
   - 시간 (테스트에서 "오늘을 12월 25일로 가정" 가능해야 함)

3. **테스트 관점:**
   - 실제 DB/메일/카톡 없이 순수 로직만 테스트 가능
   - 예: "Alice가 기한을 4일 넘겼을 때, 벌금이 정확히 2000원인가?"
   - 예: "대출 시 알림이 정확히 1회 전송되었나?"

**예시 사용:**

# 답

# 채점

전반적으로 DI의 핵심 개념인 "추상에 의존하고 구체 구현은 외부에서 주입"을 이해하고 있는 것은 맞습니다. 다만 몇 가지 중요한 문제점이 있습니다.

---

## 잘 된 부분

- 각 관심사마다 ABC(인터페이스)를 정의하고 구체 클래스를 분리한 방향은 옳습니다.
- `Service` 생성자에서 의존성을 받는 **생성자 주입** 방식을 선택한 것도 맞습니다.
- IoC 컨테이너 역할(조립 로직)을 서비스 클래스 외부에 분리한 것도 맞습니다.

---

## 문제점

**1. `DeadlinePolicy`를 `Book` 엔티티에 주입한 것 — 가장 핵심적인 오류**

`Book`은 데이터 객체(entity)입니다. 대출 기한 정책은 `Service`에 주입되어야 할 비즈니스 로직인데, `Book`에 심어버리면 정책 교체 시 `Book` 생성 코드를 전부 바꿔야 합니다. "어떤 의존성을 어디에 주입할지" 위치 판단이 잘못된 것으로, DI 패턴에서 가장 중요한 부분입니다.

**2. `Service`에 `DeadlinePolicy`와 `Clock`이 주입되지 않음**

요구사항에 명시된 두 가지 의존성이 `Service.__init__`에 없습니다. `deadline = GeneralDeadline(...)` 을 IoC 파트에서 만들었지만 `Service(db, notice, penalty)`에 전달되지 않아 연결이 끊겼습니다.

**3. 구체 클래스들이 `ABC`를 잘못 상속받음**

`KakaotalkNotice(ABC)`, `EmailNotice(ABC)` 등이 `Notice`가 아닌 `ABC`를 상속받고 있습니다. 구체 클래스는 자신의 인터페이스(`Notice`)를 상속해야 타입 호환성이 보장됩니다. 이렇게 되면 `Service`가 `Notice` 타입으로 받아도 실제로는 무관한 타입이 들어오는 셈입니다.

**4. `GeneralDeadline`, `RefferenceDeadline`이 `DeadlinePolicy`를 상속받지 않음**

인터페이스를 정의해두고 구체 클래스가 그것을 구현하지 않으면 인터페이스를 선언한 의미가 없습니다.
